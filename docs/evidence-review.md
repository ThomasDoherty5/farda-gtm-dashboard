# Source evidence and reviewer annotations

The authenticated evidence page reads a saved agent assessment and the selected native post. A source record can describe sampled visual points, continuous visual intervals, heard-audio intervals, captions, machine transcription and unassessed modalities. The original source owns playback. Opening the original does not certify watching or hearing it. Unknown, login-required, denied, unavailable and deleted access remain distinct from historical review completion.

A source packet can optionally record the observed access state, an opaque source receipt and its observation time. The saved source reviewer, review time and heard-audio intervals are also optional. Older packets preserve unknown values. These fields describe the reviewed source packet. They do not authenticate a browser session or grant permission to fetch media.

Use the standard `evidenceRecord` read with the creator and evidence IDs. Its optional `runId` selects an exact immutable assessment. Previous and next revision links retain the selected post identity and resolve against the authenticated workspace and account. The source assessment, terms revision, policy, model configuration, selected media and source packet determine the annotation basis. An updated source produces a new basis.

Reviewers can append an interval note through `evidenceDraft` or a disagreement or proposed override through `reviewerAssessment` on the standard save endpoint. The resource is the selected evidence ID. The payload binds the creator, immutable run and basis hash. The server assigns the reviewer principal. A note requires continuity across its entire interval in the relevant recorded modality. A sampled visual point or machine transcript cannot establish that interval. Disagreements reference an actual saved source fact or an existing note, and include a reason. The original fact and every prior annotation remain readable. A basis holds up to 100 entries and returns an explicit limit when full.

The SQLite transaction checks the exact expected version and idempotency key before recording an annotation and acknowledgment. The acknowledgment identifies the saved input, actor, post, revision and time. For an uncertain outcome, the editor retains that exact request in its protected scope and reads saved history. When the read confirms it, the UI acknowledges the existing entry. When the read establishes that the expected slot is still empty, a reviewer can retry the identical request with its original key. A failed read keeps the pending request held.

A disputed assessment requires fresh review. A new run, label, terms revision or configuration alone cannot remove the challenge from the same canonical or native media. A completed source review can clear a challenged source fact when it supplies a different review receipt, a review time after both the challenge and the original review, and materially changed evidence for that fact. A future timestamp, an unrelated change or a reordered source row cannot clear a specific challenged fact. Challenges to appended reviewer notes remain held for explicit resolution. Source facts, model weights, historical decisions and provider execution are never changed by the annotation endpoint.
