# Agent instructions

Frontend for the Farda GTM operations dashboard. The Linear project is the implementation handoff. Read `docs/intake.md` for the stack and commands, `docs/figma-access-gap.md` for which Figma file to read, and `docs/design-map.md` for the token and component mapping.

**This repository is public.** Never commit the Linear handoff text, Figma captures, secrets, real customer or creator data, or provider identifiers. `.handoff/` is a gitignored local snapshot of those documents. Fetch from Linear when it is missing or stale; its issue bodies are truncated at 500 characters, so use `get_issue` for acceptance criteria.

## Before changing a screen

1. Read the owning Linear issue (the owner column of `docs/figma-source-manifest.md`) and its rows in the control contract.
2. Read the Figma source node through MCP, in the file named in `docs/figma-access-gap.md`. Use the source node, not the prototype clone. Load the `figma-design-to-code` skill first.
3. Implement one reviewable vertical slice, then compare it with `scripts/compare-figma.mjs`.

If Figma is inaccessible, work only on what does not depend on it. Never guess visuals or claim fidelity.

## Where things go

| Concern | Location |
| -- | -- |
| Data access, only through `useView` and the adapter | `src/adapter/` |
| Contract types, transcribed from the adapter document | `src/adapter/contract.ts` |
| Demo datasets, kept separate and never mixed | `src/fixtures/` |
| Screens | `src/features/<area>/` |
| Shared components | `src/components/` |
| Design tokens, named as in Figma | `src/design-system/tokens.css` |
| Route manifest, generated by `npm run manifest:generate` | `src/routes/manifest.generated.ts` |

## Rules

- No provider APIs, credentials or tokens in the client. Don't invent backend URLs; THO-283 publishes them.
- An unavailable backend shows an honest pending state and never falls back to demo data. Demo data is always labeled.
- A known zero, unknown and N/A are different states. Missing data never becomes zero.
- Approved is not Sent. Show success only after the authoritative acknowledgment or source receipt.
- New acquisition is commission-only. Historical v2 scores and accepted fees stay read-only and labeled.
- 401 and 403 clear protected data. Query keys include the full scope.
- Don't weaken a test or accessibility check to pass. Don't update visual baselines from the implementation.

## Done means

`npm run verify` and `npm run test:e2e` pass. Record evidence on the owning Linear issue, and state the release stage truthfully: fixture-complete, integration-verified or production-authorized.
