# Scoped action orchestration

This module composes the approval repository and the existing job runner. It does not create an approval, finance, inventory or dispatch ledger. All externally effective handlers are trusted server registrations. No browser payload supplies a principal, role, provider URL, source receipt, gate, available balance or activation flag.

`createActionService` validates a strict operation/kind/payload/reference matrix, resolves scoped signed versions, and delegates to the owning repository. It exposes `execute`, `executeDomain`, `readApproval`, and `readRun`. The browser-safe native read schemas are in `views.ts`. Native tasks, shipments and policy actions do not acquire fabricated creator-message or commission fields. Provider locators, raw payloads and Slack identities are excluded from those projections.

A new preview and decision request use the existing J04 immutable manifest and command key. The default app decision path remains held: only the configured trusted Slack ingress and durable Linear readback establish a decision. Approved does not mean sent. Dispatch handoff freezes one actual homogeneous finite manifest/subset into one native run; a trusted worker separately performs current approval, capability, resource and lease checks. The HTTP action is never a direct provider invocation. Missing registrations or sources are explicit holds.

Signed versions preserve the exact original manifest or run revision. Replays delegate the original key/body to the owner, even after the current version changes. A current transport request ID wraps the historical receipt. Current expiry/withdrawal reasons remain visible. Typed denied outcomes preserve the exact stored applied/uncertain status without exposing protected records. Neither cache retention nor a new request key releases an uncertain native effect.

## Source-owned reporting effects

`createActionDomainServices` borrows the scoped SQLite connection and existing `JobRepository`.

- `exportSnapshot` / `exportLedger` accepts no entity, approval, manifest or input run references. A current named finance/founder directory grant and a qualified ledger source must authorize the whole exact filtered snapshot. Paging verifies snapshot identity, revision, offsets, total, currency, timestamps, uniqueness and completion; it never exports only the current UI page. Generation uses the registered bounded `export-ledger-snapshot.v1` job, checkpoints and an atomic final source/lease/artifact transaction. The receipt includes the actual run, artifact, row count, bytes, hash and expiry. Retrieval rechecks actor, scope, source permission and expiry. Output is a private UTF-8 CSV with closed columns and scoped opaque references, never an email/address/bank export. An incomplete/oversized snapshot fails explicitly. Limits are 100,000 rows, 16 MB, 1,000 job steps and five minutes; they are bounds, not hidden truncation.
- `recordSourceDecision` / `recordLaunchReadiness` accepts one exact source target with matching account/version, verdict, already sourced launch date, rationale and evidence references. A trusted named founder and qualified source writer are required. Go requires approved L, current allowed phase and passing required evidence gates. The writer must enforce the exact original idempotency key, source version and immutable intent. A valid write ACK and exact native Notion readback are retained durably; malformed/absent/lost readback is uncertain. Only a terminal no-op proof can close an unresolved request. A later request cannot overtake an unresolved target. A readiness record always has `confersRelease:false`; it does not activate production, dates, sampling, fulfillment or paid media and cannot be a J04 execution authorization.

Both source interfaces require a trusted synchronous `assertCurrent` fence following asynchronous reads. Named actor proofs additionally use the same J04 source-owned `assertAuthority` callback (the actual returned trusted-human proof, no reconstructed client role), including final response and replay fences. The readiness source additionally declares source-enforced idempotency. These functions validate existing authority; they cannot create it. The repository retains immutable source receipts and body hashes across restarts. A source adapter is not qualified merely because it implements a TypeScript interface.

`recoverReadinessRequest(requestKey, principal)` returns the original actor-scoped public target, version, exact entity tuple, payload and digest from its frozen view mapping. It can reconcile through the original source lookup, but never calls the writer. Both the receipt and recorded source version are opaque aliases. Current source permission, lease and named-founder fences run before returning protected rationale or receipt data. An absent lookup is observational only; a missing legacy public mapping is unverified. Neither permits a new-key attempt. Positive terminal nonapplication proof is retained separately from an applied receipt. A reload therefore needs only a nonsensitive original-key marker, never browser-persisted rationale.

## Existing ownership retained

Navigation, filters, selected views, local fields and source links remain reads or local UI behavior. Existing versioned offer, evidence, schedule and lifecycle saves remain saves. J14 health refresh is a separate observation operation. Locked lifecycle consent, suppression and duplicate-enrollment policies remain literal true across the three editable flows; this action service accepts no policy booleans or send flags. New business dispatch uses J04 plus the existing finite runner. Canonical task/collaboration/monitor/candidate/statement handlers remain unavailable until their owner registers and qualifies a source implementation.

The private control inventory covers every original row and records its owner and acceptance boundary. It is intentionally excluded from this public repository. A complete mapping is not a claim that every provider is connected or every screen is production authorized.

## Verification and stage

Focused tests use synthetic identities, actual scoped SQLite, actual J04 and the existing runner. They cover finite batches, native receipts, exact-key replay, changes of scope/version/body, current authority loss, unknown outcomes, private-column rejection, whole-snapshot export, final-await source withdrawal and restart recovery. Native Node import is checked separately from Vite transformation. HTTP/session/CSRF/capability integration is owned by the central server tests.

This is a source-seam implementation with synthetic integration evidence. It contains no production Slack/Linear decision write, qualified ledger export source, qualified Notion readiness writer, provider activation, send or spend.
